# Validation scope

Omitia Brain is a Markdown kit. Validation checks instruction coherence, saved artifacts and agent behavior; there is no bundled application or ingestion pipeline to build. The observations below used fictional disposable workspaces unless stated otherwise. Detailed earlier narratives remain in the [recorded version](https://github.com/Oxyz-Studio/omitia-brain/blob/3f8caed53dea815003f5e946785532d43577832e/docs/validation.md).

## External references and restricted audiences

Checklist metadata was registered without reading the document's body; a consultation-only document produced no retained source content or answer. Separate integration grants and an authorized release stayed distinct from the restricted source and its provenance. Managed derivative dependencies included later access loss without text changes.

Normal navigation recovered the permitted statements and their authority/freshness limits. Static checks found resolving links, no team link outside its proposed area and no targeted protected identifiers or amount in team files. This tested saved layout and instructions, not enforced boundaries. OS permissions, a multi-user backend, real identities, source resolvers and revocation were not configured. The fixture withheld real restricted delivery pending those controls; previous downloads, Git history and model context remain explicit revocation limits. ## What these checks do not establish

File portability, loader discovery, agent behavior, artifact integrity and enforced runtime controls are separate evidence. None proves universal model quality, every history format, actual connector/scheduler/search operation, notification delivery or real access enforcement.

A receipt supports recovery and inspection; it is not a transaction, lock or independent guarantee of semantic truth. Concurrent or high-volume environments may need stronger local controls. Backup presence does not establish a tested restore or independent backup failure domain.

For a deployment, exercise its actual identities, tools and scheduled invocation through [scheduling](scheduling.md) and [reliability](reliability.md). For kit changes, repeat the affected journey and inspect saved knowledge and retrieval under [CONTRIBUTING.md](../CONTRIBUTING.md); link checks alone cannot establish preserved meaning.
