# Choosing and carrying context

Load what the task needs and keep the rest discoverable. Use this guide with [retrieval](retrieval.md); no index or runtime memory is required.

## Start from the task and subject

Identify the work, subjects, and relevant time. The workspace or conversation can supply a default, but the current request takes precedence: a request about Lumen should not inherit Atlas's constraints from the previous thread.

Within the [authorized view](retrieval.md), read the brain's entry and policy, a relevant overview or pack when available, then the canonical subject and needed evidence. Follow links selectively. Check names, aliases, and identity before combining subjects that may be the same.

## Give each kind of context its role

| Kind | What it carries | How to use it |
| --- | --- | --- |
| Context pack | A task-oriented selection of canonical notes, with brief orientation and reasons to open them. | Use it to choose relevant reading; check the underlying notes for claims the answer depends on. |
| Descriptive domain note | Shared terms, entities, locations, states, invariants, and known limits of a subject. | Use it to interpret knowledge and apply local rules consistently. |
| Procedure, playbook, or skill | Steps and conditions for performing repeatable work. | Read it when that work is needed, within the established permissions. Use [experience to procedure](../recipes/experience-to-procedure.md) to turn an observed correction into bounded, tested guidance. |

These roles can be sections; no extra folders or three files per subject are required. Packs are derived views: link durable rules to their canonical home. Use the optional [context-pack template](../templates/context-pack.md) where helpful.

A saved domain contract does not prove a tool reads it; verify the reader before claiming integration. Procedures can link domain definitions instead of repeating them.

Links and text search are often enough. Follow relationships for dependencies or prior reasoning; add an index or graph only for recurring retrieval problems. Keep knowledge and evidence usable without it.

## Keep runtime memory compact

If the host loads memory across conversations, reserve it for brief, stable orientation that changes behavior, matters frequently, and is costly to forget: a durable preference, standing constraint, or pointer to the brain's entry or canonical rule.

Keep dated state, measurements, versions, inventories, uncertain facts, and history in the brain; repeatable instructions in procedures. A useful conversation detail need not become permanent runtime memory.

Before relying on a memory, home, or summary pointer, open its destination and check the knowledge and validity. If broken, seek another permitted canonical path and state remaining limits; the pointer's old wording is not verified knowledge.

Consolidate or remove low-value memory entries within the write policy. Before replacing detail with a pointer, verify that its destination preserves the knowledge and is discoverable. Do not raise memory limits to avoid selection; the kit sets no runtime-specific size threshold.

## Bound the reading, then expand for a reason

Start with directly relevant notes. Expand for an identified gap: a referent, decision reason, source qualification, conflict, or dependency. Do not follow every related link.

Stop when useful assertions and material limits are supported. Break broad tasks into bounded questions, carrying concise findings and evidence locators. Open long sources at relevant sections. A search result limit does not bound subsequent reading.

Use the given time, cost, or context budget; adapt reading to complexity and consequence rather than a fixed note count. Preserve gaps and resume points when verification exceeds the budget. Reading already authorized needs no fresh approval.

When useful, record which notes determined the answer and why without reproducing their content. Test selection and recovery with the [retrieval checks](../examples/retrieval-checks.md) and optional [case template](../templates/retrieval-case.md).
