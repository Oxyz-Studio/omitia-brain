# Keep useful work without repeated requests

When the private policy already authorizes integration of the current work's sources, actions, retention, destination and audience, **save useful new knowledge without waiting for another request to remember it**. Use this contract during ordinary work and authorized conversation ingestion. A permission to read, a writable folder or a broad maintenance grant alone does not authorize retaining every conversation.

## Act at a useful point in the work

After resolving a meaningful question, comparing options, receiving a supported correction or checking a repeatable fix, decide whether the outcome will help later work. Keep decisions and their reasons, reusable analyses, constraints and bounded lessons. Skip routine chatter, repeated summaries, unsupported generalizations and facts already represented correctly. Do not create a note or receipt after every answer merely to show activity.

Read the private entry, applicable permissions and canonical subject before saving. Use the recorded method version for any method guidance needed. A known source, standing grant and destination need no fresh approval. If a required permission or destination is unknown, continue the user's task within scope and identify the specific gap; do not silently create a brain or search other histories to fill it.

An explicit read-only request, `check`, metadata-only `discover`, or a consultation-only source prevents retention of that material even when routine maintenance is otherwise permitted. Keep the current action's boundaries. Do not write a content-bearing receipt or refusal as a substitute for a prohibited note.

## Keep the result, its evidence and its limits

- For a comparison or analysis, follow [the synthesis path](../recipes/direct-contributions.md#preserve-a-useful-synthesis-from-a-question). Distinguish an agent recommendation from the user's decision and retain the dependencies needed to review it later.
- For an observed correction or repeatable method, follow [experience to procedure](../recipes/experience-to-procedure.md). Save an untested explanation as a candidate, not a validated operating rule. Standing permission to keep knowledge is not permission to execute an additional test or change an external system.
- For a decision, correction or factual change, update the existing canonical account under the brain's authority rules, with the relevant source, effective scope and changed views.

Use the actual conversation or contribution reference and examined range when available, plus the underlying documents or execution evidence. If the host exposes no stable conversation locator, record the available contribution identity, date and permitted bounded evidence with that limitation; do not invent a session ID or claim the whole history was read. Preserve only what retention allows. An agent's synthesis is not independent proof of its source claims.

Apply the existing [continuity contract](continuity.md): save a proportionate receipt, verify ordinary retrieval and retain incomplete work when evidence or readback is missing. One record can serve several roles. Reuse prior knowledge and receipts rather than producing a second account of the same finding. Mention a material saved result briefly in the normal task handoff, following the user's reporting preferences; no extra approval question is needed.

## Combine in-work capture with history ingestion

| Path | Purpose | Boundary |
| --- | --- | --- |
| Working agent | Preserve a useful outcome while the relevant evidence is available. | Uses only the current permitted work; does not establish coverage of other agents or past sessions. |
| Authorized history ingestion | Revisit eligible conversations and changed versions, recover missing context and catch findings not saved during work. | Uses registered sources, actual source access and bounded coverage; works without a reminder hook. |
| Optional consultation skill, standing pointer or hook | Route the agent to its private entry and this contract when relevant work occurs. | Does not grant retention, install a schedule or guarantee every session is captured. |

When ingestion encounters something already saved during work, compare meaning, provenance and covered source version/range. Add genuinely new evidence or repair a gap when authorized; otherwise record the reviewed unit as `no-durable-change` using the normal receipt. A quoted brain summary is not another independent confirmation. If the earlier save lacks usable coverage, inspect the source before finalizing that coverage rather than trusting its existence.

At setup or an approved method update, adapt this behavior into the private agent entry and any consultation skill so everyday work can use it without rereading the public kit. Record actual grants; do not turn this contract into a default permission. Keep one private rule referenced by entry points. Existing brains retain their method pin until an approved update.
